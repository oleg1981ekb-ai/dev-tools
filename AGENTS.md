# AGENTS.md

Инструкции и контекст для AI-агентов и ассистентов, работающих с этим репозиторием.
(Стандарт: [agents.md](https://agents.md).)

## О проекте

`dev-tools` — личный monorepo-инкубатор утилит одного разработчика
(`oleg1981ekb-ai`). Стратегия — **«инкубатор → продукт»**: проект живёт здесь,
пока не созреет для отдельного репозитория. Критерии и порядок выделения —
в разделе «Стратегия развития» [README.md](README.md).

Актуальный план работ и состояние задач — в [TODO.md](TODO.md).
**Обновляй `TODO.md` при закрытии или появлении задач.**

## Правила (обязательны)

1. **Секреты и данные клиентов — никогда в git.** Файлы `.env`
   (`GROQ_API_KEY`), PDF-чертежи, `raw_extracted_text.txt` исключены через
   `.gitignore` (корневой и в `bim-estimate-ai/`). Не ослабляй эти правила.
2. **Один коммит — одна тема.** Не смешивать уборку, рефакторинг и
   функциональные правки.
3. **Тематические ветки:** `main` — стабильное состояние; фичи — в `feature/*`,
   затем PR в `main`. Текущая рабочая ветка генератора — `feature/interactive-tasks`.
4. **Не коммитить мусор:** `.DS_Store`, `__pycache__`, `.venv`, `.~lock.*`,
   `temp.zip` (уже в `.gitignore`).
5. **CI генератора** срабатывает только при изменении `gantt-generator/**`
   (фильтр `paths`). Новые CI добавляй с такими же фильтрами.
6. **Архитектурные решения — в ADR.** Любое значимое решение
   (выбор метода/формата/стратегии, отказ от альтернативы) фиксируй файлом
   `docs/adr/NNNN-*.md` (следующий номер = max+1) в формате
   Контекст → Решение → Последствия. Триггеры: «почему так, а не иначе»,
   «что пробовали и отбросили», смена подхода в ветке.
   Принятый ADR не правится задним числом — отмена только новым ADR.
   При закрытии задачи проверь: нужно ли записать ADR, обновить `TODO.md`.
7. **Ченджлог.** При мерже задачи в `main` добавь запись в `CHANGELOG.md`
   соответствующего продукта (раздел `Unreleased`, категория
   `Added/Changed/Fixed/Removed`). Пиши языком пользователя («что изменилось»),
   не языком коммитов; номер PR — в скобках. Технические детали — в ADR.
   Корневой `CHANGELOG.md` — только для изменений уровня репо.

8. **Не сливать ветки в `main` без явного согласования.** Слияние (merge,
   squash-merge, rebase на main) любой ветки в `main` производится только
   после прямого подтверждения пользователя. Коммитить в feature-ветки можно,
   но вливать в `main` — только по команде.

## Конвенции кода

- Python 3.11+ (CI использует 3.11), стиль — без форматтера пока, читаемость и
  русские комментарии/выводы в консоль — принятая практика проекта.
- Зависимости — в `requirements.txt` рядом со скриптом.
- Скрипты — консольные, интерактивный ввод через `input()`, вывод с эмодзи-статусами
  (✅ ❌ 🚀) — это принятый стиль UX данных утилит.
- Пути в `bim-estimate-ai` — относительные от `Path(__file__)` (PR #3);
  PDF ищется сам в `data/`, либо передаётся аргументом.
- Архитектурные решения — см. правило 6 (ADR обязательны, формат
  `docs/adr/NNNN-*.md`).
