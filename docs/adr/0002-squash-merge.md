# ADR-0002: Squash-merge PR в `main`

Дата: 2026-10-17
Статус: принято

## Контекст

Рабочий процесс: фичи в ветках `feature/*`, вливание в `main` через
Pull Request. Встал вопрос, как именно сливать: обычным merge-коммитом,
rebase или squash.

## Решение

PR сливаем методом **Squash and merge**: вся ветка сжимается в один
коммит в `main`, номер PR сохраняется в сообщении
(пример: `feat(bim-estimate): ... (#4)`).
Ветка после мержа удаляется (локально и на GitHub).

## Последствия

+ История `main` — «одна задача = один коммит», читается как changelog.
+ По номеру PR всегда находится обсуждение и дифф задачи.
− Теряется внутренняя детализация ветки (промежуточные коммиты видны
  только в закрытом PR на GitHub, не в `git log main`).
− Не подходит, если внутри ветки есть отдельно ценные коммиты —
  тогда дробить задачу на несколько PR заранее.
