# Архитектурные решения (ADR)

Индекс и правила ведения ADR. Обязательность ADR закреплена правилом 6
в [AGENTS.md](../../AGENTS.md).

## Формат

Файл: `NNNN-краткое-имя.md` (нумерация с ведущими нулями).
Структура: **Контекст → Решение → Последствия**.

- Дата — в формате `YYYY-MM-DD`.
- Статус: `принято`, `отменено`, `заменено` (с указанием нового ADR).
- Принятый ADR не правится задним числом: изменение решения оформляется
  новым ADR, старый получает статус `отменено`/`заменено`.

## Когда писать ADR

- Выбор метода, формата, библиотеки или стратегии.
- Отказ от альтернативы, которую стоит помнить («почему не так»).
- Смена подхода в ветке или пересмотр ранее принятого решения.

При закрытии задачи проверь: нужен ли ADR, обновлены ли `TODO.md` и
`CHANGELOG.md`.
