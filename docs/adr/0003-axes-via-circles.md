# ADR-0003: Цифровые оси ищем по кружкам из векторного слоя, а не по краевым зонам

Дата: 2026-10-17
Статус: принято (PR #5, ветка `feature/bim-estimate-axes`)

## Контекст

Для привязки перегородок к сетке осей нужно найти цифровые оси (2..11)
на кладочном плане АР. Первая версия сканера (v1) искала одиночные цифры
в краевых зонах 15% листа.

## Решение

Ось = цифра **внутри векторного кружка** из `page.get_drawings()`
(диаметр ~28 pt, правильная окружность) + проверка монотонности ряда
(≥80%). Три детектора: кружки (главный), ряд в линию (допуск 12 pt),
фильтр выносок (кружки вразнобой / немонотонные — не оси).

## Последствия

+ Ровно 10 осей 2..11, ноль ложных срабатываний (v1 давала 6 с мусором).
+ Маркер-выноска «1» у стрелки фрагмента больше не ломает ряд.
− Ось «1» не найдена в кружках (открытый вопрос: левее x=269 или
  подписана иначе — проверить по чертежу вручную).
− Зависимость от векторного слоя: на сканированном PDF (растр без
  векторов) метод не сработает — понадобится OCR/растровый детектор.
− v1 отброшена по измеренным причинам: нижняя зона 15% (y>1431)
  отсекла настоящий ряд (y≈1418, не хватило 13 pt); правило «один символ»
  отвергло оси «10», «11»; ловился мусор вида «2»/«3» на кромке.
